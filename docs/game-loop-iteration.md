# 如意鲜果蛋糕游戏化创作迭代记录

## 本次目标

把普通的 AI 蛋糕设计表单，迭代成更接近小游戏的创作流程：用户接任务、选道具、获得创作值、生成作品、微调升级、发布给蛋糕师报价。

## 核心选择补全

当前不是只保留一个方向，而是把三个方向按优先级串成连续版本：

### 三个版本方向

1. 玩法增长优先：v0.3 已优先落地。重点是每日任务、AI Bot 点评、灵感券、玫瑰、投票和作品广场，让用户先愿意打开、生成、微调和发布。
2. 传播裂变优先：作为 v0.4 的主要方向。重点是作品详情页、分享海报、好友投票、送玫瑰、做同款、榜单和回流提醒，让一个作品带来更多新玩家。
3. 交易转化优先：作为 v0.5 的主要方向。重点是发布制作需求、附近蛋糕师报价、报价选择、订单恢复、履约状态和售后反馈，让好设计能真正变成蛋糕采购。

### 三条主闭环

1. 任务创作闭环：AI Bot 派发任务 -> 用户接任务 -> 生成/微调蛋糕图 -> 发布作品 -> AI Bot 点评 -> 获得投票、玫瑰和待审灵感券。
2. 作品传播闭环：作品广场展示 -> 用户分享给朋友 -> 好友投票/送玫瑰/认同点评 -> 作品热度上升 -> 其他用户做同款或参与同主题任务。
3. 制作交易闭环：用户从自己的作品或他人作品发起制作需求 -> 就近蛋糕师报价 -> 用户选择师傅 -> 双方确认细节 -> 制作、配送/自提、评价和售后。

版本推进原则：v0.3 先把任务创作闭环跑顺；v0.4 补作品传播闭环；v0.5 再加强制作交易闭环。交易入口保留，但不在创作数据尚未跑通前过早扩展复杂支付和履约。

## 已实现

- 首页增加“今日挑战”。
- 设计页增加“灵感任务”。
- 设计页增加“装饰道具”。
- 设计页增加“创作值”和“创作徽章”。
- 生成时会把任务、道具、创作目标拼入 AI prompt。
- 结果页展示创作值、徽章、任务和道具。
- 微调作品后会提升创作值并标记为“微调升级”。
- 作品列表升级为“作品广场”。
- 用户可以采用作品广场中的设计进入结果页。
- 发布制作需求后获得 `+20` 创作值奖励。
- “我的”页展示累计创作值。
- AI Bot 每天派发蛋糕设计任务。
- 任务展示灵感券点数，审核版不展示现金奖励承诺。
- 发布需求后，灵感券进入“待审核”状态。
- 作品广场已明确定位为“蛋糕设计论坛”。
- 首页升级为“AI Bot 派单 + 玩家设计端 + 蛋糕师傅端”的双角色入口。
- “我的”页拆分为玩家设计端和蛋糕师傅端两个工作台。
- 蛋糕师傅端展示服务范围、接单数据、健康证和营业执照状态。
- 作品广场加入热度、采用次数、评论数、AI 首评和制作建议。
- 结果页加入审美Bot、制作Bot、预算Bot的多角色点评。
- 首页重新收敛为采购用户的快速上手入口，只保留定位、开始设计、我的订单、今日灵感。
- 新增“我的订单”页面，承接设计、需求、报价、支付、制作配送和配送员信息。
- 确认报价意向后会生成订单意向，并进入“我的订单”查看后续沟通和履约状态。
- 增加每日签到领玫瑰，玫瑰可送给喜欢的蛋糕设计。
- 作品和结果页增加观众投票、送玫瑰，并在本地限制同一用户同一作品只能操作一次。
- AI 点评角色改为深度求索、通义千问、豆包、文心一言、腾讯混元、讯飞星火，只保留境内模型/品牌语义。
- 真实用户可对 AI 点评点“认同”，同一用户同一条点评只能认同一次。
- 发布制作需求增加日期、配送方式、人数、口味、预算、地址、联系方式、是否允许调整等明细。
- 蛋糕师报价增加蛋糕价格、配送费、制作周期、可制作日期、报价说明和还原调整说明。
- 作品投票、送玫瑰、AI 点评认同已接入后端持久化。
- 每日签到领玫瑰已接入后端钱包，同一用户同一天只能签到一次。
- 灵感券已接入后端审核，后台通过后同步钱包待审/可用点数。
- 用户售后投诉已改为用户侧公开接口，进入后台工单队列。
- 蛋糕师入驻页已支持上传健康证、营业执照、食品经营相关资质图片，并进入后台审核。
- v0.3 新增后端 `DesignTask`、`DesignTaskJoin`、`DesignTaskCompletion`，每日任务、接任务、完成任务和奖励待审已后端化。
- v0.3 新增 `BOT_LLM_PROVIDER=mock|doubao|deepseek` 文案服务，支持 AI Bot 生成任务候选和作品多角色点评；缺密钥或失败时自动回退本地境内评审席模板。
- 首页和设计页优先读取 `/design-tasks/today`，后端不可用时才回退本地季节任务。
- 结果页提交作品广场审核或发布制作需求时，会调用 `/design-tasks/:id/complete`，同一用户同一任务只能完成一次。
- “我的”页新增“任务/灵感券”区，展示已完成任务、待审灵感券、可用灵感券和玫瑰余额。

## 奖励机制边界

审核版不展示 RMB 自动奖励。若未来恢复现金激励，正式上线前必须补齐：

- 作品审核。
- 需求审核。
- 奖励发放规则。
- 防刷规则。
- 用户实名或收款信息规则。
- 后台人工确认。

未完成审核闭环前，不能把奖励做成自动到账。

## 当前仍需继续后端化的部分

当前已经把核心互动和审核数据落到后端 JSON 持久化。仍需继续后端化：

- 用户积分的长期等级体系。
- 作品热度。
- 分享次数。
- 发布需求转化。
- 蛋糕师报价转化。
- 城市榜单。
- 真实评论。
- 真实配送状态。

## 下一步建议

1. 做“蛋糕师接单倒计时”：提高需求紧迫感。
2. 做“好友投票”：让用户分享作品获得投票。
3. 接真实登录后，把积分、奖励和作品归属落到真实用户。
4. 把作品广场改成只展示审核通过/公开作品。
5. 把创作值、采用次数和发布奖励落数据库。
6. 做运营后台的奖励审核和发放记录。
7. 做蛋糕师入驻资料上传、后台审核和服务范围配置。
8. 做作品详情页，承载真实评论、投票、采用记录和蛋糕师建议。
9. 接入城市定位：后端 IP 库或腾讯地图逆地理编码，把用户城市用于附近蛋糕师和配送范围匹配。
10. 接入真实同城配送或门店自配送状态，替换当前配送员模拟信息。
11. 把投票、玫瑰、AI点评认同和每日签到落数据库，并用真实用户 ID 做防重复。
12. 把发布需求和报价明细拆成后端结构化字段，便于后续搜索、筛选和风控。
